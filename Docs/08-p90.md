# FN P90 — première intégration

La P90 reprend `VBCombatWeapon`, donc `BaseCombatWeapon`, et l'inventaire
natif déjà utilisés par le pistolet. Le tir automatique, la cadence, les
traces, les dégâts, les chargeurs, le rechargement, le ramassage et le drop
restent dans cette chaîne. L'intention de jeu est la P90 de Stargate SG-1 :
une arme compacte, rapide et contrôlable, sans tir secondaire.

## Utilisation

Placer `Assets/weapons/p90/p90.prefab` dans une scène puis ramasser l'arme
avec l'action `use`. Le prefab embarque sa représentation physique au sol
et son repère d'interaction. Le HUD, les slots et les restrictions de
traversée existants s'appliquent automatiquement.

| Réglage | Valeur initiale |
|---|---:|
| Chargeur | 50 |
| Réserve au premier ramassage | 50 |
| Réserve maximale 5,7 × 28 mm | 150 |
| Tir | Automatique, 900 coups/minute |
| Dégâts par balle | 14 |
| Rechargement | 2,8 s |
| Sortie d'arme | 0,45 s |
| Encombrement | 3 |
| Précision en visée | Dispersion × 0,45 |

Ces valeurs sont des réglages de jeu, modifiables dans le prefab.
`AimSpreadMultiplier`, `RecoilPitch`, `RecoilYaw` et `AimRecoilMultiplier`
sont communs aux armes ; leurs valeurs par défaut conservent le comportement
précédent du pistolet.

## Bras et animations existantes

Le mesh fourni `weapons/p90/mesh/p90.vmdl_c` est un prop sans animation
ni attache de canon. Il est affiché par un `ModelRenderer` statique ; un
renderer skinné sans animation déforme ce prop.

`weapons/p90/v_p90.prefab` utilise le modèle officiel **Facepunch ViewModel
MP5** (`facepunch.v_mp5`, `models/weapons/sbox_smg_mp5/v_mp5.vmdl`) comme
donneur d'animation. Ses meshes sont masqués (`BodyGroups = 0`), son
animgraph natif reste actif. Les bras humains officiels utilisent le
`BoneMergeTarget` natif vers ce squelette, comme ceux du pistolet.

Les événements de `BaseWeaponModel` déclenchent les animations de sortie,
de tir et de rechargement. La visée utilise le paramètre natif `ironsights`.
Le petit composant `VBWeaponMeshAttachment` fixe la P90 à l'os animé
`weapon_root` ; il ne pilote ni animation, ni tir, ni rechargement.

### Ajustement du placement

1. Ouvrir `Assets/weapons/p90/v_p90.prefab`.
2. Sélectionner **P90 Mesh - Adjust Grip Here**.
3. Régler sa position, sa rotation et éventuellement son échelle locales.
   Cette pose est conservée lors du rattachement au squelette en jeu.
4. Régler les enfants `muzzle` et `eject` si nécessaire. Le canon doit
   correspondre à l'extrémité réelle du modèle ; l'éjection est orientée
   vers le bas.
5. Ajuster séparément le mesh dans `w_p90.prefab` pour la prise en main TPS.
6. Affiner les offsets ADS sur le composant `VBCombatWeapon` si nécessaire.

Le placement est une base à ajuster, comme convenu. La gestuelle MP5 est
une animation de substitution : sa main gauche ne manipule pas le chargeur
supérieur d'une vraie P90. Une animation P90 dédiée sera nécessaire pour
reproduire ce geste. Le chargeur visible reste solidaire de l'arme.

`PreferMuzzleMarker = true` garantit que les tirs et effets utilisent le
repère de la P90 plutôt que l'attache du MP5 masqué.

## Assets et son

Les matériaux du modèle proviennent du package déjà installé `greg.p90`.
Les prefabs le déclarent dans leurs références, ainsi que les dépendances
Facepunch du viewmodel. Le fichier compilé fourni est conservé explicitement
dans Git, car il n'a pas de source `.vmdl` dans le projet. Les chemins de
ressources utilisent `.vmdl`, résolu par le moteur vers `.vmdl_c`.

`sounds/weapons/p90/fire.sound` utilise l'échantillon ajouté par l'utilisateur,
`sounds/weapons/p90/fire_1.wav`. Les retours chargeur faible, vide et tir à sec
sont ceux déjà présents dans le projet.

Le tireur local entend un son 2D sans occlusion, atténuation par distance,
absorption ou réverbération simulée. Le callback natif de présentation garde
les impacts et traceurs ; les événements d'attaque du modèle sont déclenchés
une seule fois. Les autres joueurs et les armes dans le monde conservent le
son 3D natif et les réglages acoustiques du fichier `.sound`.

La compilation .NET et le rechargement dans l'éditeur sont validés. Le test
audio dans le moteur vérifie 12 événements successifs par échantillon (P90
et pistolet), leur volume fixe, l'absence de traitement acoustique local et
la conservation du son 3D natif dans le monde : 73 contrôles validés.
